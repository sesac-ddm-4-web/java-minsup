## 4. 구현 중 해결한 문제

### 문제 1: split 대신 정규식으로 단어 추출
- **문제**: 구분자가 다양해 `split`으로는 기호가 붙은 토큰이 남음
- **원인**: `split`은 버릴 것을 정의하므로 구분자를 하나라도 빠뜨리면 오염됨
- **해결**: `[a-zA-Z0-9가-힣ㄱ-ㅎㅏ-ㅣ]+`로 남길 단어를 정의하고 `Matcher.find()` 반복
- **확인 결과**: [ ] (실제 돌린 입력/출력)

### 문제 2: 임시 맵(`localCounts`) 제거
- **문제**: 실패 파일이 결과를 오염시킬까 봐 임시 맵을 두었음
- **원인 분석**: `parse()`가 텍스트 전체를 반환한 뒤에 집계하므로 집계 중 예외가 없음
- **해결**: 임시 맵 제거, 루프에서 바로 `addWordCount`
- **확인 결과**: 형식 오류 CSV가 섞인 폴더에서 실패 파일 단어가 집계에 없음 [ ] (실제 확인)

### 문제 3: (택1) 경로 입력 예외 / 폴더 분석 버그
- **문제 / 원인 / 해결 / 확인 결과**: [ ] 실제 겪은 것만 작성

## 7. AI 활용 내용과 직접 확인한 방법

| AI에게 물은 것 | 받은 답 | 직접 확인한 방법 |
|---|---|---|
| 전체 처리 흐름 설명 | 흐름 정리, 폴더 처리 버그 지적 | 코드를 다시 읽고 `entry` 인자 수정 후 폴더 입력 테스트 |
| 정규식 vs split 차이 | 남길 것/버릴 것 개념 | 같은 문자열로 두 방식 직접 실행 비교 |
| `localCounts` 필요성 | 집계 구간에 예외 없음 | 형식 오류 파일로 실행해 확인 |
